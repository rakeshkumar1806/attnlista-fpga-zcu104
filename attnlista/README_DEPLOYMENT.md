# ZCU104 AttnLISTA Deployment Handoff

This document contains the exact hardware configuration extracted from the exported `system_bd_wrapper.xsa`. Because the local machine lacks the Vitis IDE toolchain, you will use these details to build the bare-metal C++ application on a machine with Vitis installed.

## 1. DMA-to-Port Mapping

There are **5** total AXI DMA engines in this design to handle the 64-bit serialized streaming interfaces of the HLS cores. Below is the exact routing as extracted from `build_final_bd.tcl`:

1. **`dma_lista_y_out`**
   - **MM2S (TX):** Feeds pilot input vectors into `lista_core/y`
   - **S2MM (RX):** Receives the final output of the LISTA iterations from `lista_core/h_out`
2. **`dma_lista_init`**
   - **S2MM (RX):** Receives the Least-Squares skip-connection output from `lista_core/h_ls_init_out`
3. **`dma_cnn_refine_out`**
   - **MM2S (TX):** Feeds LISTA's final output into the CNN's first input stream `cnn_core/refine_input_1`
   - **S2MM (RX):** Receives the final, completely refined output from `cnn_core/out_r`
4. **`dma_cnn_refine_2`**
   - **MM2S (TX):** Feeds LISTA's skip-connection output into the CNN's second input stream `cnn_core/refine_input_2`
5. **`dma_cnn_res` (The 5th Channel)**
   - **MM2S (TX):** Feeds LISTA's final output *again* directly into the CNN's `cnn_core/residual_base` port. **What this is:** The CNN architecture specifies a final skip connection where the original LISTA output is added to the CNN's processed output. This 5th DMA channel streams the original LISTA output directly to the end of the CNN pipeline to perform that final hardware addition.

## 2. AXI-Lite Memory Map

The Zynq PS controls the HLS cores and DMAs via the following memory-mapped base addresses. You can use these to verify the `xparameters.h` macros generated by Vitis match the real hardware:

| IP Block | Base Address | Range |
|----------|--------------|-------|
| `lista_core` | `0xA0000000` | 64K (`0x10000`) |
| `cnn_core` | `0xA0010000` | 64K (`0x10000`) |
| `dma_lista_y_out` | `0xA0020000` | 64K (`0x10000`) |
| `dma_lista_init` | `0xA0030000` | 64K (`0x10000`) |
| `dma_cnn_refine_out` | `0xA0040000` | 64K (`0x10000`) |
| `dma_cnn_refine_2` | `0xA0050000` | 64K (`0x10000`) |
| `dma_cnn_res` | `0xA0060000` | 64K (`0x10000`) |

## 3. UART Configuration

The Zynq UltraScale+ PS UART (UART0) is configured for the standard ZCU104 baud rate: **115200 8-N-1**.

## 4. Vitis IDE Build Checklist

On a machine with Vitis IDE 2022.2 installed, follow these steps:

- [ ] Open Vitis IDE and set a new workspace directory.
- [ ] Click **Create Platform Project**. Provide a name (e.g., `attnlista_hw`) and point it to the generated `system_bd_wrapper.xsa`.
- [ ] Build the Platform Project (this generates the BSP and `xparameters.h`).
- [ ] Click **New Application Project**, select the `attnlista_hw` platform, and choose the `standalone` domain for `psu_cortexa53_0`.
- [ ] Select the **Empty Application (C++)** template.
- [ ] Copy the generated `main.cpp` and `test_vectors.h` (located in the project folder) into the application's `src/` directory.
- [ ] **Build** the Application Project.
- [ ] Connect the physical ZCU104 board via USB (JTAG/UART). Open a serial terminal (PuTTY/TeraTerm) at 115200 baud.
- [ ] Right-click the Application Project -> **Run As** -> **Launch on Hardware (Single Application Debug)**.

## 5. Expected Output

A successful run will print the initialization steps over UART, execute both cores, compute the Mean Squared Error against the baked-in golden Python test vectors, and output a line resembling:
`Final Hardware NMSE vs Golden Model: 0.000001` (or roughly `-60 dB`).
